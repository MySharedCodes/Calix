# 公开发行准备

Calix 自有源码已采用 [GPL-3.0-only](../LICENSE)，公开源码仓库为 [MySharedCodes/Calix](https://github.com/MySharedCodes/Calix)。当前本地 Windows 程序和安装包未签名，尚未公开二进制发行文件。详细状态和签名步骤见[许可证、仓库与代码签名](LICENSING.md)。

## 公开仓库前

1. 确认源码权属、第三方代码和示例素材的授权。项目自有文件采用 GPLv3，仅第 3 版；保留完整许可证、版权及修改声明。
2. 核对[许可证审查记录](LICENSE-REVIEW.md)和实际打包依赖，特别是 MPL 源码义务及二级许可证兼容性。当前捆绑 Intel 运行库的 GPLv3 组合分发兼容性尚未解决；公开组合二进制前需替换为兼容的求解器与运行库或取得充分授权。不能仅凭“可选模块”认定可分发。
3. 检查 `.gitignore` 与实际暂存内容。排除 `work/`、`App/`、`release/`、`tools/`、虚拟环境、缓存、个人笔记和凭据。忽略规则不能移除已经提交的秘密；如有泄露应先撤销凭据并处理历史。
4. 再审阅根目录和文档中的绝对本机路径、个人名称、旧日志与截图。首次公开前完成敏感信息扫描和人工检查。
5. 在确定的仓库创建 Issues 与私密安全报告入口，再填写 README 中的真实地址。下载链接必须指向实际可用的发布资产。

## 发布内容

README 应让首次访问者迅速看到：软件名称、一张真实截图、适用问题、三步开始方式、兼容性边界，以及帮助、案例、贡献入口。保持中英首页同步。版本号、安装包名、文档和变更记录一致。

可以使用准确的主题标签，例如 `calculator`、`symbolic-math`、`scientific-computing`、`notebook`、`units`、`finite-element-method`、`windows`。不要使用未达到的兼容性、性能或认证声明。

发布说明包含本次问题及改进、已知限制、支持系统、可选组件、GPL-3.0-only、仓库及同版本源码地址、签名状态、校验值和升级方法。截图来自实际版本，不用概念图替代。当前界面示例见 `docs/images/`。

二进制发行应按 GPLv3 第 6 条提供相应源码及构建、安装脚本。保存匹配版本标签和源码归档；通用仓库首页或依赖清单不能代替对应源码。现有安装包早于本次许可证变更，需重新构建并核对配套许可文件。

## 验证与打包

- 按 [开发说明](DEVELOPMENT.md) 构建，运行与修改相关的检查和 `scripts/check-docs.py`。
- 在新 Windows 用户或干净虚拟机测试安装、首次计算、F1 离线帮助、保存和重新打开，以及升级保留偏好。
- 分别测试基础安装和含 PDE module、附加语言、皮肤的安装。验证缺少模块时错误清楚。
- 核对 UI、CLI 与便携目录的版本及配套运行库；生成并复核 SHA256。确认 notices 和所需第三方源码实际随包提供。
- 配置可信代码签名证书或服务，先签名 Calix 自有程序和 DLL，再制作并签名最终定制安装包。验证预期发布者、签名和时间戳后生成 SHA256；详见[签名步骤](LICENSING.md)。尚未完成时如实标为未签名。

源码仓库已公开；完成上述二进制发行检查后再建立发行 tag 与 Release、上传安装包。源码公开不表示签名、打包和二进制验收已经完成。
