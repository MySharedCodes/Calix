# 公开发行准备

此文档是维护者检查表，不表示项目已经开源或发布。仓库地址和应用许可证由维护者决定；当前仍适用根目录 [LICENSE](../LICENSE)。

## 公开仓库前

1. 确定源码权属、第三方代码和示例素材的授权，再选择应用许可证。许可选择要同时覆盖源码与预期分发方式，不能只修改 README 徽章。
2. 核对 [许可证审查记录](LICENSE-REVIEW.md) 和实际打包依赖，特别是 Eigen 的 MPL 源码义务及 Intel 运行库的分发条款。应用开源不代表所有二进制组件同许可证。
3. 检查 `.gitignore` 与实际暂存内容。排除 `work/`、`App/`、`release/`、`tools/`、虚拟环境、缓存、个人笔记和凭据。忽略规则不能移除已经提交的秘密；如有泄露应先撤销凭据并处理历史。
4. 再审阅根目录和文档中的绝对本机路径、个人名称、旧日志与截图。首次公开前完成敏感信息扫描和人工检查。
5. 在确定的仓库创建 Issues 与私密安全报告入口，再填写 README 中的真实地址。下载链接必须指向实际可用的发布资产。

## 发布内容

README 应让首次访问者迅速看到：软件名称、一张真实截图、适用问题、三步开始方式、兼容性边界，以及帮助、案例、贡献入口。保持中英首页同步。版本号、安装包名、文档和变更记录一致。

可以使用准确的主题标签，例如 `calculator`、`symbolic-math`、`scientific-computing`、`notebook`、`units`、`finite-element-method`、`windows`。不要使用未达到的兼容性、性能或认证声明。

发布说明包含本次问题及改进、已知限制、支持系统、可选组件、校验值和升级方法。截图来自实际版本，不用概念图替代。当前界面示例见 `docs/images/`。

## 验证与打包

- 按 [开发说明](DEVELOPMENT.md) 构建，运行与修改相关的检查和 `scripts/check-docs.py`。
- 在新 Windows 用户或干净虚拟机测试安装、首次计算、F1 离线帮助、保存和重新打开，以及升级保留偏好。
- 分别测试基础安装和含 PDE module、附加语言、皮肤的安装。验证缺少模块时错误清楚。
- 核对 UI、CLI 与便携目录的版本及配套运行库；生成并复核 SHA256。确认 notices 和所需第三方源码实际随包提供。
- 对公开 Windows 安装包评估代码签名；如未签名，应如实说明。不要通过删除安全软件来解决安装提示。

完成这些检查后再建立 tag 与 Release、上传安装包。本文不执行公开、上传或更改许可证。
